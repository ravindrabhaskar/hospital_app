Fix these first

Ordered by how easily they can be exploited or how directly they harm a patient. Items 1–7 are code changes of a day or less each.

  1. Shut down the public demo tunnel and stop running the dev API behind trycloudflare. Anyone with the URL can log in as super admin with OTP 123456.
    Today · ops
  2. Make partner webhook secrets mandatory in production, and don't register webhook routes for disabled partners. Today a known dev secret lets anyone forge WhatsApp check-ins, vitals, lab results and SOS events.
    Hours · API
  3. Set trustProxy to the real load-balancer hop and make OTP/MFA attempt counting atomic. Together these close OTP brute force.
    Hours · API
  4. Stop discharges from auto-granting access to existing patients. Any hospital desk user can currently give themselves full access to any patient. Send the patient an invite to accept instead.
    A day · API
  5. Fix the Razorpay payment.failed handling so a retried card doesn't leave a paid patient with no booking, and make refunds and cancels race-safe.
    1–2 days · API
  6. Make the no-pack prescription warning blocking, and keep a built-in minimum set of emergency rules when no safety pack is approved.
    Hours · API
  7. Gate the mobile "Server address" setting on debug builds, stop the provider app wiping its offline queue on a 5xx, and rebuild dist/android with an https API URL.
    1–2 days · mobile
  8. Make deploys depend on CI passing, pin GitHub Actions to commit SHAs, and confirm production environment approvals exist in GitHub.
    A day · CI
  9. Reconcile the store declarations with the build (Health Connect, HealthKit, privacy manifest), or remove the health permissions.
    Before any store submission
  10. Clinical and legal sign-off: an approved safety rule pack with evaluation results, a CDSCO medical-device opinion, counsel review of consent text and cross-border AI processing, and a named Grievance Officer.
    Before any real patient data

All findings

What is already done well

Authentication

Pinned HS256 JWT with issuer and audience checks, 15-minute expiry, session and user status re-checked on every request, rotating hashed refresh tokens with reuse detection, TOTP MFA with encrypted secrets and replay protection.

Production guardrails

The API refuses to start in production with dev JWT or payment secrets, console SMS, mock gateways or partners, no ClamAV, or no MFA key.

Data access

Central assertCanActForPatient with audited denials, zod validation on effectively every route, fully parameterised SQL, append-only audit and episode tables enforced by DB triggers.

AI safety design

The deterministic safety engine runs before any model call, emergencies use a fixed template, severity only goes up, and model output is grounded and policy-filtered.

Uploads and headers

Content-sniffed allow-listed file types, ClamAV scanning, path-safe storage keys, Helmet with a deny-all CSP, HSTS, and PHI redaction in logs.

Infrastructure

AWS Mumbai region, private KMS-encrypted RDS with forced TLS and 14-day point-in-time recovery, CMK-encrypted S3, OIDC deploys, non-root containers. No secrets anywhere in git history.

Not covered by this audit

This was a static code review plus the local test suites. It did not include:
  • Live GitHub settings: whether the repo is public, branch and tag protection, environment approvals.
  • The live AWS account, penetration testing, or DAST against a running stack.
  • Testing under real Postgres concurrency. All tests run on single-connection PGlite, so race conditions are found by reading code only.
  • Code coverage, because @vitest/coverage-v8 is not installed.
  • Legal advice. The compliance findings show where the code and the obligations don't match; counsel should confirm them.
