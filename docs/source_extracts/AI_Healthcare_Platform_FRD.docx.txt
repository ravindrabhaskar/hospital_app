11. Fall Detection
Receive supported device event.
Prompt user to confirm safety.
If safe, close event.
If help requested/no response, notify configured contact.
Escalate through supported emergency workflow.
Store incident metadata.

19. Error Handling
Scenario
 | System behavior
 | AI unavailable
 | Show safe fallback and offer human/provider pathway.
 | Payment failure
 | Do not confirm paid service; allow retry.
 | Provider unavailable
 | Offer alternate slot/provider.
 | Poor image
 | Request retake.
 | Network failure
 | Preserve safe local state where permitted; retry.
 | Emergency signal
 | Prioritize escalation workflow over normal chatbot response.
 | 20. Functional Acceptance Criteria
All P0 requirements pass functional testing.
Role permissions prevent unauthorized access.
Core patient-to-provider journey works end-to-end.
AI safety rules trigger defined escalation cases.
Records are stored and retrieved correctly.
Home visits can be booked, assigned and completed.
Audit records are generated for sensitive actions.
Critical notifications are delivered through configured channels.
